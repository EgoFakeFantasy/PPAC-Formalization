## 接受定义独立于比较规格

PureSyntaxExprQuery.query(e,w,env)是对象EX行码，要求实际HornExprSyntax.graph(e,w,env,row)及原纯十五规则闭轨迹接受该row。OriginalTransformExprQuery.query使用同样的实际图结构，但接受条件来自原完整变换规则表的HornLookupConditionSyntax.condition。

两种rowQuery对应原精确constructor及同一接受条件。constructor_query_iff消去两边实际EX行见证，使用已证的原Expr节点字段图双条件，不在定义中引用Term／TermList／FormulaCode／FreeSubst规格或Expr.eval。PureSyntaxQueryTyping进一步给出三种原语法行表达式与纯类型的全内部双条件。

这些是固定原Rule／Expr描述符的纯关系式编译。它们尚未与扩展BasicSetTheory语言中的ObjectHorn.condition原生公式作完整quotation消去等价，不能据此宣称原宿主Bool检查器或全内部Option接口已经对应。

## 原substitutionShape查询与模式字段

PureProofSubstitutionQueries的substitutionFormula／substitutionArguments／substitutionTransform直接选择原ObjectProofNode.substitutionShape.queries的第0／1／4项表达式。actual_formula／actual_arguments／actual_transform和CheckStep4用rfl核对原Kind与确切原字段：

```text
0: syntax node4[0,env2,env5]
1: syntax node1[0,env0,env2,env3]
4: transform node3[3,0,env3,env5,env1]
```

六个赋值仍为内部自然数。env0是替换目标free界，env2是源free界，env3是实际替换项列表码，env5是源公式码，env1是输出公式码；env4为本批未处理的前驱证明引用。

原公式查询对象等价于FormulaCode(w,env5,z,env2)；原项列查询等价于TermList(w,env2,z,env0,env3)，其中Empty(z)。原mode3变换表达式与实际五字段原run对象等价，随后由真实两项纯语法查询恢复合法输入，接入原自由替换独立程序。数码3在对象EX中实际取得并消去，不把内部模式字段改为宿主常量值假设。

## 三查询合取的最终双条件

PureProofSubstitutionTransform.bundle仅合取上述三个实际查询，不引用比较规格。bundle_iff最终合同为：

```text
Ω(w) → EnvironmentNat6(w,env) → Empty(z) →
  [QuerySyntax(F) ∧ (QuerySyntax(A) ∧ QueryOriginalTransform(T))]
    ↔ [FormulaCode(w,env5,z,env2) ∧
       FreeSubstProgram(w,z,env2,env0,env3,env5,env1)].
```

没有FormulaCode、TermList、IH、Num3、预设行码或公共轨迹前提。反向利用独立程序的真实空绑定界项列表输入，通过原列表双条件恢复参数查询，再恢复原变换查询。

本合同只覆盖三项查询。原第2／3项前驱投影查询、节点head及外层有界赋值量词未包含，故完整局部检查器门仍为false。
