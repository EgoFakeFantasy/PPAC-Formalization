## 独立定义的实际接受与准确递归式

实际接受式的定义只含原tag2三字段行和关系式Packet条件，没有引用算术答案或递归criterion：

```text
Tok(w,n,t,a) = ∃r (Row_2(w,n,t,a,r) ∧ Condition_Packet(w,r))
A_B(w,d,q,n) = B∈w ∧ d∈B ∧ q∈w ∧ n∈w ∧
  ∃p (Product(w,B,q,p) ∧ Sum(w,d,p,n))
```

B、C分别是实际内部Num128、Num256。原nativeZF中的结论为：

```text
close(Ω(w) → Num128(B) → Num256(C) →
  (Tok(w,n,t,a) ↔
    ((n∈B ∧ A_C(w,n,t,a)) ∨
      ∃d,q,u,y (A_B(w,d,q,n) ∧ ¬Empty(q) ∧ Sum(w,d,B,y) ∧
        Tok(w,q,t,u) ∧ A_C(w,y,u,a)))))
```

这是真实递归Tok前提，未改成未证明的运行正确性oracle。n、t、a、digit、quotient及全部见证是任意内部集合；原ALL3将所有数据候选保留在量词域，包括非自然数。最终定理签名仅需Ω／Num128／Num256，没有V、根r或IH前提。

指定真实根另有ALL4：Row_2(w,n,t,a,r)推出Condition_Packet(w,r)与同一criterion的双条件。实际系统存在定理仅需Ω，在对象EX2中取得B、C并合成ALL3和ALL4；两种字面量没有通过宿主选择函数抽取。

在实际规范V中，任意tag条目的成员性通过V成员↔Condition与独立tagAccepted等价；tag0／1再通过前批完整内部仿射定理取得Entry↔A_B／A_C。递归tag2条目保留为真实Tok。

## 准确分支选择和非法值拒绝

由原逆分解停止条件Empty(q)↔n<B，LargeCase中的¬Empty(q)严格排除n<B，因而两个分支不会被混用：

```text
n∈B  → (Tok(w,n,t,a) ↔ A_C(w,n,t,a))
¬n∈B → (Tok(w,n,t,a) ↔ LargeCase(w,B,C,n,t,a))
```

另外从Tok的真实根得到三个字段均在内部ω；对任意i:Fin3，若相应n／tail／output字段不在ω，则Tok被对象证明拒绝。没有把输入有效性仅放在外部测试集。
